Chapter 1: Introduction & Installation

The Attendance Processor represents a paradigm shift in local application architecture. Built for absolute speed, offline reliability, and transparency, it processes massive biometric Excel exports instantly.

1.1 The PyWebView Architecture

Rather than relying on heavy server frameworks (like Django or NodeJS) or bulky Electron wrappers, the application uses PyWebView. It opens a native OS window (WebView2 on Windows, WebKit on macOS) to render a pristine HTML/JS interface.

All CSS parsing (Tailwind) is embedded directly into the source. All database operations happen natively in Python, and the two communicate seamlessly via a shared window.pywebview.api object. This means zero HTTP overhead, zero CORS issues, and total offline capability.

1.2 Installation & Setup Guide

To run the application, you have two choices: use the compiled release executable, or run from Python source.

Method A: Compiled Release (Recommended)

Navigate to the GitHub Releases page and download the ZIP file for your operating system.

  • Windows: Extract the ZIP. Double click AttendanceProcessor.exe.
    Windows SmartScreen Warning: Because this is an unsigned indie application, Windows Defender will flag it as "Unrecognized App". Click More Info and then click Run Anyway.
  • macOS: Extract the TAR.GZ. Double click the AttendanceProcessor binary.
    Gatekeeper Warning: macOS will block it, saying it is from an unidentified developer. Go to System Settings > Privacy & Security, scroll down, and click Allow Anyway.

Method B: Running from Source

If you prefer complete code transparency, you can run the app directly using Python or Anaconda:

# 1. Clone the repository
git clone https://github.com/utkarsh-brainstorm/Employee_nightmare.git
cd Employee_nightmare

# 2. Create a virtual environment (optional but recommended)
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# 3. Install requirements
pip install -r requirements.txt

# 4. Run the application
python main.py

Chapter 2: The Core Logic Engine (Parser)

The parser engine is responsible for digesting messy Secureye ONtime Excel exports and translating them into pristine, mathematically strict SQLite rows.

2.1 The Month Boundary Algorithm

The ONtime software spreads 31 days horizontally across columns, but repeats these headers on multiple pages. Because reports often span across two different months (e.g., July 25th to August 24th), the parser uses a custom algorithm to detect when the day numbers loop backward (e.g., from 31 back to 1) and automatically iterates the month counter.

2.2 The Absolute Presence Rule (V9 Engine)

Prior versions of the software attempted to calculate whether an employee was "Present" based on how many hours they worked. This caused massive errors if employees forgot to punch out. In V9, we implemented the Absolute Presence Rule:

# Dynamic status logic based strictly on presence of any punch
if punch_in or punch_out:
    status = "PRESENT"
else:
    status = "ABSENT"

The Rule: If there is literally any biometric record associated with an employee on a given day, their database status is permanently locked to PRESENT. The penalty for missing hours is resolved by the financial engine, NOT by pretending they didn't show up.

2.3 The 12:00 PM Single-Punch Heuristic

If the biometric machine only gives us a single timestamp for a day (e.g., 10:45), the engine must guess if this was an arrival or a departure. It relies on a strict Noon threshold:

  • Timestamp < 12:00 PM ➜ Assumed as Punch In (Punch Out becomes NULL).
  • Timestamp ≥ 12:00 PM ➜ Assumed as Punch Out (Punch In becomes NULL).
Re-Importing Fixes: If you are upgrading from an older version, the old rows in your database might still say ABSENT. You must click the Re-import button to force the new V9 engine to overwrite the database rows with the correct Absolute Presence status!

Chapter 3: The Financial & Salary Engine

This is the mathematical brain of the application. The def_salary macro computes salaries down to the exact minute, bypassing human subjectivity entirely.

3.1 Custom Schedules vs Global Defaults

When computing shift minutes, the engine looks at the Staff Directory first. If an employee has a custom Arrival Time and Departure Time assigned, it uses those. If those fields are blank, it falls back to the Global Check-in/out times defined in the Settings tab. This creates the baseline Shift Minutes constraint.

3.2 Valid Worked Minutes Calculation

To prevent employees from artificially inflating their paycheck by arriving at 6:00 AM for a 9:00 AM shift, the engine ruthlessly caps their payable time at their scheduled shift boundaries using SQLite MAX/MIN functions:

Effective Arrival   = MAX(Actual Punch In, Scheduled Arrival)
Effective Departure = MIN(Actual Punch Out, Scheduled Departure)

Valid Worked Minutes = Effective Departure - Effective Arrival

3.3 The 50% Single-Punch Penalty Rule

What happens if an employee only punched in, but never punched out? We cannot subtract NULL from a timestamp. To resolve this, the engine deploys a mathematical heuristic built directly into the SQL:

WHEN (a.punch_in IS NOT NULL OR a.punch_out IS NOT NULL) THEN
  (strftime('%s', Scheduled_Departure) - strftime('%s', Scheduled_Arrival)) / 120

By subtracting the scheduled boundaries to get the total shift duration in seconds, and dividing by 120 (which is exactly equivalent to dividing shift minutes by 2), the system automatically credits the employee with exactly 50% of their scheduled shift. They are docked half a day's pay to enforce biometric compliance, without losing the entire day.

3.4 The 1-Day Paid Leave Credit Rule

The system possesses a built-in forgiveness protocol. If an employee's status='ABSENT' count is greater than 0, they are automatically granted a Leave Credit of 1.

This adds exactly one full day of Shift Minutes to their Payable Mins total. Therefore, every employee receives 1 paid absence per month. If they are absent 0 times, the credit is ignored. If they are absent 4 times, they are only financially penalized for 3 of them.

3.5 Final Salary Formula

The final payout is determined by creating an ultra-accurate Per-Minute Rate:

Working Days = Total Days in Date Range - Global Calendar Holidays
Per-Minute Rate = Monthly Base Salary / (Shift Minutes × Working Days)

Earned Salary = Payable Mins × Per-Minute Rate

Chapter 4: Quick Reports (Macros)

The sidebar contains four "Quick Reports". These are complex, pre-written SQL macros that execute instantly.

4.1 Monthly Summary

Provides a sweeping overview of the entire workforce. It aggregates total PRESENT, ABSENT, WEEKLY_OFF, and HALF_DAY counts. It computes total hours worked, average hours per day, and dynamically subtracts Calendar Holidays from the global Working Days calculation.

4.2 Absentees

This macro returns a detailed list of every employee who was marked ABSENT on any day. Crucially, it includes an exclusion join: AND a.work_date NOT IN (SELECT date FROM calendar_days). This ensures that employees are not falsely flagged as absent on global holidays (like Sundays or National Holidays).

4.3 Salary Report

Executes the massive minute-by-minute financial engine detailed in Chapter 3. Generates the final Earned (₹) column.

4.4 Perfect Attendance

Rewards compliance. This query uses a strict HAVING clause to filter the workforce down to only those who have exactly 0 Absences (excluding holidays) and 0 Half Days.

Chapter 5: User Interface & Query Builder

The application features a deeply customizable Single-Page Application (SPA) interface, designed for power users.

5.1 The Visual Query Builder

Instead of forcing users to write SQL, the interface provides dropdowns for Fields, Operators, and Values. You can stack as many AND/OR conditions as you want.

  • Text fields (e.g. Employee Name): Support contains, starts with, ends with. This translates to LIKE '%value%' in SQL.
  • Time fields: Support before and after.

5.2 Aggregate & Group Panel

For advanced data crunching, you can select Aggregates (like SUM(Hours) or COUNT(*)) and group them by fields (like Employee Name or Month).

5.3 The Dual-Mode Conflict Engine

A common error in standard SQL is mixing GROUP BY clauses with raw, non-aggregated columns. If a user asks to group by "Employee Name" but also selects "Punch In Time", SQLite will simply return a random row's punch time, leading to wildly inaccurate reports.

The SPA intercepts this using the validateGroupBy() algorithm. If it detects a conflict before running, it blocks execution and explicitly tells the user which columns are invalid, ensuring the math is always flawless.

5.4 Zoom & Resizing

You can zoom the entire interface by pressing CTRL + and CTRL - (or CMD + on Mac). You can also click and drag the vertical gray divider lines to resize the Filter panel and Quick Reports panel to fit your monitor.

Chapter 6: Global Settings & Overrides

6.1 The Interactive Calendar

In the Settings Modal, the Calendar tab allows you to visually click days to mark them as Holidays. When clicked, these dates are injected into the calendar_days SQLite table. Every Quick Report automatically references this table to ensure holidays are never counted as working days or absences.

6.2 The Staff Directory

This panel allows you to override data for specific employees based on their Emp Code. You can set a custom display name, define their Monthly Base Salary, or assign custom Check-In/Out boundaries. You can also toggle Disabled to completely hide an employee from all reports.

6.3 The Query Log

For total transparency, every single SQL query executed by the frontend (including macros and custom filters) is logged to the query_log database table. You can view this in the Settings modal. It keeps the last 100 queries, allowing you to copy the exact SQL and run it manually.

Chapter 7: PDF & CSV Exporter

Any result grid generated by the system can be instantly exported.

7.1 CSV Export

The CSV engine dumps the exact, raw dataset from the grid into a UTF-8-SIG encoded file. This ensures it opens perfectly in Microsoft Excel without character encoding corruption.

7.2 PDF Export (ReportLab)

The PDF engine dynamically generates a beautiful document. If you upload an Organisation Logo in the Settings, it automatically calculates the aspect ratio and embeds it at the top of the PDF. The table uses alternating row colors based on the current UI theme. Finally, if you execute a custom SQL query, the PDF engine appends the exact SQL code at the bottom of the document so you have a permanent record of how the math was achieved.
